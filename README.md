# Контроль облачной инфраструктуры, вариант 27

КТ1 - пять тестовых значений

## 1. Назначение программы

Программа считает, как изменились показатели трех компонентов облака за k отсчетов, определяет в норме компонент или нет и ищет инциденты, когда не в норме сразу два или три компонента. Пока данные из карточки записаны прямо в коде.

## 2. Описание индивидуального варианта

- компоненты: PWR, LAT, QRY
- запись: компонент, время, значение через запятую
- есть записи с чужими кодами, их надо пропускать
- показатель Q - относительное изменение, k = 3, L = 2.0
- состояние: если |Q| > L то ТРЕВОГА, иначе НОРМА
- инцидент: не в норме хотя бы 2 компонента из 3
- Incident: time (номер отсчета), type (тип), count (сколько компонентов не в норме)

$$Q_i = \frac{X_i - X_{i-k}}{X_{i-k}}$$

Инцидент (a, b, c - PWR, LAT, QRY не в норме):

$$Inc = (a \land b) \lor (a \land c) \lor (b \land c)$$

## 3. Описание инфраструктурных компонентов

- PWR - потребление энергии сервером
- LAT - задержка ответа
- QRY - количество запросов

## 4. Формат исходных данных

Строка из карточки:

```
QRY,3,32.4,ZZZ,5,81.0,PWR,5,52.9,QRY,5,30.9,PWR,4,47.0,LAT,2,53.6,LAT,3,57.0,LAT,1,55.6,PWR,2,46.0,QRY,1,33.9,LAT,4,55.0,PWR,3,46.5,QRY,4,31.6,QRY,2,33.1,PWR,1,45.5,LAT,5,53.0,ZZZ,2,78.0
```

Каждая запись это код, номер отсчета и значение. ZZZ не мой компонент, его выкидываю.

## Ручной расчет

Разложил по времени:

| t | PWR | LAT | QRY |
|---|---|---|---|
| 1 | 45.5 | 55.6 | 33.9 |
| 2 | 46.0 | 53.6 | 33.1 |
| 3 | 46.5 | 57.0 | 32.4 |
| 4 | 47.0 | 55.0 | 31.6 |
| 5 | 52.9 | 53.0 | 30.9 |

При k = 3 Q можно посчитать только для t = 4 и t = 5:

| | t = 4 | t = 5 |
|---|---|---|
| PWR | (47.0 - 45.5) / 45.5 = 0.0330 | (52.9 - 46.0) / 46.0 = 0.1500 |
| LAT | (55.0 - 55.6) / 55.6 = -0.0108 | (53.0 - 53.6) / 53.6 = -0.0112 |
| QRY | (31.6 - 33.9) / 33.9 = -0.0678 | (30.9 - 33.1) / 33.1 = -0.0665 |

## Ожидаемый результат

Все |Q| меньше 2.0, тоесть все компоненты в НОРМЕ, a = b = c = 0. Инцидентов 0.
